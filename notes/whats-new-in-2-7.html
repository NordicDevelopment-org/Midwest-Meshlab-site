What’s new in Meshtastic 2.7

Release summaryRead 5 minTags Firmware · Release
Where this comes from

Compiled from the Meshtastic firmware release notes and project blog, linked below. Version numbers are what those sources showed when this was written on 29 Aug 2026 — check the releases page for what is current before you flash.

The 2.7 series is the most visible change Meshtastic has shipped in a while. If you have been running 2.6 and wondering whether it is worth moving, the short answer is that the interface is genuinely different, and a few of the under-the-hood changes matter for congested meshes.

BaseUI: the default interface, rebuilt

The headline is a rebuilt and renamed default interface, BaseUI — described by the project as the largest overhaul of the default UI in over four years. The goal was an interface that is more capable and works sensibly across a much wider range of screens, from tiny OLEDs to the larger displays on newer boards.

If you have muscle memory from older firmware, expect to spend a few minutes relearning where things live.

Multi-message storage

Nodes can now batch several messages together before transmitting rather than sending each as its own packet. Fewer discrete packets hitting the channel means less airtime contention, which is most noticeable on a busy mesh where channel utilisation is already high.

If your local mesh regularly runs hot, this is the change most likely to help you.

Configurable API port

The API port can now be set from the config file rather than relying on the default. That matters if you run more than one service against the same device, or build your own tooling against the Meshtastic API and want the port pinned rather than assumed.

Hardware and logging

  • Support for the ThinkNode M7.
  • A rotating JSONL recorder for persistent logging — useful if you are trying to characterise a flaky link over days rather than minutes.

Which build should you run?

Meshtastic ships alpha and beta builds continuously, so “the latest” moves constantly. At the time of writing the 2.7 line had progressed through several alpha builds — 2.7.18, 2.7.22 and 2.7.24 — to 2.7.26 marked beta.

Check before you flash

Those version numbers were accurate when this page was written and will be stale soon after. Always take the current build from the releases page rather than from a blog post — this one included. And on a node that is deployed somewhere inconvenient, let a build sit in beta a while before you climb the mast.

Before you upgrade

  • Back up your channel configuration, or at least have the QR code somewhere you can reach it.
  • Skim the open issues for your specific board — several current reports are hardware-specific rather than general. Our known-issues note covers what to look for.
  • Upgrade one node first, confirm it still talks to the mesh, and only then do the rest.
